# Color image example

Draws a full-screen 128x128 color image plus a 32x32 sprite on the ST7735,
straight out of flash — the TLSR8232 has nowhere near enough RAM for a
framebuffer (16 KB of RAM vs 32 KB for one full-screen RGB565 frame), so pixels
are streamed to the panel as they are read.

![sunset](assets/sunset.png)

| What | How |
| ---- | --- |
| Background, 128x128 | `display_draw_image_rle()` — 860 bytes of flash instead of 32768 |
| Sprite, opaque | `display_draw_image()` — one address window, no per-pixel re-addressing |
| Sprite, transparent | `gfx_draw_rgb_bitmap_with_mask()` — 1bpp alpha mask, background shows through |

## Pixel format: BGR565, not RGB565

This panel is wired with red and blue swapped (see `display_color()` in
[display.c](../../lib/display/display.c)), so image data must be stored as
`bbbbbggg gggrrrrr`. `tools/img2c.py` already emits that. If you convert an
image with some other tool and everything comes out blue-tinted, that's why.

## Converting your own image

```bash
# full-screen background, run-length encoded
python3 ../../tools/img2c.py assets/sunset.png --name sunset --rle -o sunset.h

# sprite with a transparency mask taken from the PNG's alpha channel
python3 ../../tools/img2c.py assets/heart.png --name heart --alpha-mask -o heart.h

# resize on the way in
python3 ../../tools/img2c.py photo.png --size 64 --name photo -o photo.h
```

The converter is pure stdlib Python — no Pillow. It reads 8-bit PNGs
(grayscale / RGB / RGBA / palette, non-interlaced); if yours is 16-bit or
interlaced, re-export it as 8-bit RGBA first.

Useful flags:

| Flag | Effect |
| ---- | ------ |
| `--rle` | run-length encode; huge win for flat art, a loss for photos |
| `--alpha-mask` | also emit `NAME_mask[]` for `gfx_draw_rgb_bitmap_with_mask()` |
| `--bg RRGGBB` | color that transparent pixels get flattened onto (default black) |
| `--size N` / `--width` / `--height` | nearest-neighbor resize |

Check the size comment at the top of the generated header before committing it —
raw 128x128 is 32 KB, which is a meaningful chunk of the F512's flash (and more
than fits at all on an F128 alongside a BLE stack).

## Sample artwork

`assets/sunset.png` and `assets/heart.png` are generated by
[assets/make_assets.py](assets/make_assets.py), so there is no binary art to
trust in the repo. Regenerate with `python3 make_assets.py` inside `assets/`.

## Build and flash

```bash
docker run --rm -v $(pwd)/../..:/src -w /src/examples/image -it tlsr8232-sdk \
  make SDK=/opt/8232_BLE_SDK/ble_sdk_hawk

cd ../../tools/tlsr82-debugger-client
python tlsr82-debugger-client.py --serial-port /dev/ttyACM0 \
  write_flash ../../examples/image/_build/image.bin
```

> The example mounts the repo root rather than just the example directory,
> because the Makefile pulls in `lib/display` and `lib/fonts`.
